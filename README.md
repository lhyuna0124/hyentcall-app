# ENT 응급콜 관리 (entcall-app)

이비인후과 전공의 응급실 백콜 노티 작성 + 입원 통계 + 전공의 역량 평가를 위한 Next.js 앱입니다.

## 1. 로컬에서 실행

```bash
npm install
npm run dev
```

`http://localhost:3000` 접속. KV 환경변수가 없으면 메모리 저장소로 자동 동작합니다 (서버 재시작 시 데이터 초기화).

## 2. Vercel 배포

1. 이 폴더를 GitHub 저장소에 올린 뒤 Vercel에서 Import → Deploy.
2. 데이터를 영구 저장하려면 Upstash 무료 Redis를 연결하세요 (Vercel Marketplace를 통한 연결은 카드 등록을 요구할 수 있어,
   아래처럼 Upstash에 직접 가입하는 방법을 권장합니다 — 카드 없이 무료로 사용 가능):
   1. https://console.upstash.com 에서 무료 가입
   2. "Create Database" → Redis 선택, 이름 정하고 Region은 가까운 곳(예: ap-northeast) 선택, **Free** 플랜으로 생성
   3. 생성된 데이터베이스 상세 페이지의 "REST API" 섹션에서 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` 두 값을 복사
   4. Vercel 프로젝트 → Settings → Environment Variables 에 위 두 이름 그대로 값 붙여넣기 후 저장
   5. Deployments 탭에서 최신 배포 Redeploy
   이 두 환경변수가 없으면 메모리 저장소로 자동 동작하며(재배포 시 초기화), 있으면 자동으로 영구 저장됩니다.

## 3. 계정 설정 (중요)

`lib/residents.ts` 에서 이름/연차/로그인용 휴대폰 뒷 4자리를 실제 값으로 반드시 교체하세요.
현재는 예시로 `0000` 이 들어가 있습니다. 관리자 계정(`isAdmin: true`)도 같은 파일에서 설정합니다.

> 이 로그인 방식은 이름 + 전화번호 뒷 4자리만 확인하는 **간단한 인증**입니다.
> 환자 개인정보(등록번호 등)는 저장하지 않도록 설계했지만, 노티 기록에 환자 이름/나이/진단명이 남습니다.
> 병원 내부망 전용으로만 접근 가능하게 하거나(사내 VPN, IP 제한), 최소한 URL을 외부에 공유하지 않는 것을 권장합니다.
> 더 강한 보안이 필요하면 NextAuth + 병원 SSO 연동을 추가로 고려하세요.

## 4. 주요 화면

- `/` 로그인 (이름 + 휴대폰 뒷 4자리)
- `/notify` 응급 노티 작성 — 신체진찰 체크박스, Lab 붙여넣기 자동 인식(▲▼ 표시), Neck CT 소견 입력.
  "최종 format 생성/미리보기"를 누르면 입력 섹션들이 자동으로 접히고, 바로 아래에 위험도별로 색이 다른 권장 노티 방식(진단명 + 위험도 + 작성자 본인의 해당 질환 역량 평가 반영)이 표시됩니다.
  작성 중간에 "임시저장"으로 브라우저에 저장해두었다가 나중에 이어 쓸 수 있고, 최종 저장 시 입원결정/OPD f/u/타과 의뢰/전원 중 하나를 선택합니다. 담당 교수는 박민규/이현아/곽진혜 중 선택합니다.
- `/stats` 날짜별/전공의별 통계. 각 기록을 펼치면 입력했던 상세 내용(신체진찰, Lab, CT, 치료계획, 당시 권장 노티 방식)과 시간을 확인할 수 있고, 새벽(00~06시) 노티는 표시가 구분됩니다. 잘못 입력된 기록은 삭제할 수 있습니다.
- `/admin` (관리자 전용) 전공의별 요약, 역량 평가 입력/삭제, 응급질환 위험도 알고리즘 수정
- `/tools/chart-review` 차트리뷰 포맷터 — EHR에서 복사한 Neck CT/Thyroid US/ANA/혈액검사 결과를 붙여넣으면 환자번호·판독의·처방일 등 불필요한 정보와 검사일시·단위를 제거하고 정리해줍니다.
- `/tools/us-report` US Report 작성 — 기존에 쓰시던 사전 기반 자동완성(자유 입력) 방식과, 체크박스/선택 방식으로 바로 만드는 선택형 방식 두 가지를 제공합니다.
- `/tools/mdt` 다학제(MDT) 환자 정리 — 구리/서울병원을 먼저 선택한 뒤 환자 인적사항·수술/병리·영상검사를 입력해 요약을 생성합니다. 등록번호/이름/요약이 서버(Upstash)에 저장되어 로그인한 누구나 이어서 조회·수정할 수 있습니다.
- `/tools/lab` 실험실 — 곧 추가될 기능을 미리 테스트해보는 공간입니다. 지금은 수술동의서 양식(`lib/consentProcedures.ts`에 수술 목록 정의)을 테스트 중이며, 전공의 누구나 댓글로 술 전 준비사항/동의서에 담을 내용을 제안하면 관리자가 "편집" 버튼으로 양식 내용에 반영합니다.

## 5. 위험도 알고리즘 기본값

`lib/triage.ts` 에 정의되어 있고, 관리자 화면(`/admin`)에서 즉시 수정할 수 있습니다.

- **즉시 입원(HIGH) 기본 대상**: Airway trauma, Postop bleeding, Deep neck infection, Acute epiglottitis
- **위험도 자동 상향 규칙**: True vocal cord 미확인 시 HIGH, Epiglottis swelling(+) + Dyspnea 동반 시 HIGH

## 6. Lab 정상범위

`lib/labRules.ts` 에서 병원 검사실 기준으로 low/high 값을 조정하세요. WBC/CRP는 항상 표기되고,
그 외 항목은 이상치일 때만 자동으로 노티 텍스트에 포함됩니다 (▲ 상승 / ▼ 저하).

## 7. 노티(연락) 방식 제안 — 요약

앱에 넣은 기본 규칙(`lib/contactPolicy.ts`)은 아래 원칙을 코드로 옮긴 것입니다. 실제 운영하며 과 정서/병원 상황에 맞게 조정하세요.

- **HIGH (airway trauma, postop bleeding, deep neck, epiglottitis 등)**: 시간대 무관 반드시 전화. 미응답 시 5분 간격 재발신, 2회 실패하면 차상급자(치프/당직 교수)로 에스컬레이션. 카톡은 "왔다갔다 확인" 용도가 아니라 백업 기록용으로만.
- **MEDIUM**: 주간엔 전화가 기본. 새벽엔 정리된 노티장을 카톡으로 먼저 보내고 10~15분 내 회신이 없으면 전화로 전환.
- **LOW**: 정리된 노티장을 카톡으로 보내고 30분 내 회신이 없을 때만 전화 1회. 해당 질환에 대해 관리자 평가 점수가 높은(예: 4~5점) 전공의라면, 통상적인 케이스는 노티 후 통상 진행하고 사후 보고만으로도 무방하도록 과 내 규칙을 정하는 걸 추천합니다 — 이러면 신뢰도가 쌓인 질환에 대해서만 선별적으로 "새벽에 전화 안 받아도 우선 진행" 규칙을 적용할 수 있어, 저년차 전공의의 '교수님 노티 마음고생'과 상급자의 '새벽에 계속 깨는 부담'을 함께 줄일 수 있습니다.
  - 예를 들어 **고년차(해당 질환 역량 평가 4~5점)** 이면서, 단순 Acute tonsillitis / Acute parotitis / Cervical lymphadenitis처럼 **처음부터 LOW 위험도**인 진단은 카톡 노티 후 회신 대기 없이 통상 진행 + 입원장 바로 발부까지 가능하도록 안내됩니다 (airway 소견이 정상인 경우).
  - **Peritonsillar abscess**는 fluctuant/pus 저류 가능성 때문에 기본 위험도가 MEDIUM으로 설정되어 있지만, 노티 작성 화면에서 **Aspiration/I&D 시행 + Pus drain "다량" + Airway 소견 전부 정상**이 확인되면 자동으로 LOW로 낮아져, 위와 동일하게 고년차는 새벽에 전화 없이 카톡만으로 진행할 수 있습니다 (`app/notify/page.tsx`의 `risk` 계산 로직).
- 다만 **airway compromise 가능성이 조금이라도 있는 케이스(TVC 미확인 포함)는 역량 점수와 무관하게 항상 즉시 전화 원칙**을 유지하는 것을 권장합니다.

## 9. 담당 교수 목록 수정

`lib/types.ts`의 `PROFESSORS` 배열(현재 박민규/이현아/곽진혜)을 수정하면 됩니다.

## 10. MDT 환자 데이터 관련 유의사항

`/tools/mdt`는 환자 등록번호와 이름을 서버(Upstash)에 저장합니다. 로그인한 사람이면 누구나(같은 계정 체계를 쓰는 전공의/교수 전원) 조회·수정·삭제할 수 있는 공용 목록입니다. 병원 내부망 전용 접근, URL 비공개 유지 등 접근 통제에 특히 신경 써주세요.

## 11. 자료실 (인계장 PDF / 수술 설명 이미지)

`/tools/resources` 페이지에서 파일을 바로 볼 수 있습니다. 방법:

1. PDF나 이미지 파일을 `public/resources/` 폴더 안에 넣습니다 (예: `public/resources/handover.pdf`).
2. `lib/resources.ts`의 `RESOURCES` 배열에 항목을 추가합니다:
   ```ts
   { title: "이비인후과 인계장", filename: "handover.pdf", type: "pdf", category: "인계장" },
   ```
3. GitHub에 커밋하면 Vercel이 자동으로 재배포하면서 `public/` 폴더 안의 파일이 그대로 `https://내주소/resources/파일명`으로 열립니다.

PPT는 "파일 → 다른 이름으로 저장 → PNG/JPEG"로 슬라이드별 이미지로 내보낸 뒤 같은 방식으로 등록하면, 자료실 화면에서 썸네일 그리드로 보이고 클릭하면 크게 볼 수 있습니다.

파일 용량이 크면(특히 고화질 PPT 이미지) GitHub 저장소 용량과 배포 속도에 영향을 줄 수 있으니, 너무 큰 원본 대신 적당히 압축한 이미지를 권장합니다.
